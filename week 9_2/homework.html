01. Minified CSS

Removed whitespaces, line breaks and formatting in CSS that increased the file size.

Before

.events-grid {
  display: grid;
  grid-template-columns: repeat(2, 1fr);
  gap: 1.25rem;
}
.event-card {
  background: var(--white);
  border: 1px solid var(--line);
  border-radius: var(--radius);
  overflow: hidden;
  display: flex; flex-direction: column;
  box-shadow: var(--shadow-card);
  transition: transform .15s, box-shadow .15s;
}

After

.events-grid { display: grid; grid-template-columns: repeat(2, 1fr); gap: 1.25rem;}
.event-card { background: var(--white); border: 1px solid var(--line); border-radius: var(--radius); overflow: hidden; display: flex; flex-direction: column; box-shadow: var(--shadow-card); transition: transform .15s, box-shadow .15s;}

Removed whitespace in the CSS to reduce file size as there are lesser data being transferred and can slightly imrpove page loading performance.

04 — Why was the webpage already peforming well?

Webpage was already lightweight

The webpage did not load any heavy libraries or frameworks, and it only contained HTML for event cards, CSS for layout, colouring and responsive design, and a small amount of Javascript for filtering, searching and implementing RSVP interactions. Thus the webpage did not have much things slowing down performance

Images were not used

CSS gradient were used as background for cards instead of actual images, keeping cost to render low as network requests were not needed, less downloading and decoding, as well as because CSS gradients are generated by the browser.

Javascript is small

The webpage only used Javascript for simple filtering, searching and toggling of RSVP or not. There was no heavy calculations or large datasets needed to be processed.
